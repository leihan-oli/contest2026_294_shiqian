# 同 FSBL 裸机金标准对照法（实施细节）

> SKILL.md「核心战术」的展开：如何在**同一条自制 FSBL 启动链**上，
> 用裸机程序作为金标准与可编程探针，对照调试 RTOS 驱动。

## 0. 前提与适用边界

| 前提 | 说明 |
|------|------|
| 启动链可控 | 自制 FSBL（或官方 boot）固定不变，RTOS 与裸机**烧到同一槽位** |
| 裸机工具链可用 | STM32Cube HAL/LL + 参考工程（如 `baremetal_tfcard` / `baremetal_lrun`） |
| 有独立串口输出 | 裸机与 RTOS 都能在**最早阶段**（进 main / `__start_c`）直写 UART |

**不适用**：没有裸机参考（半导体厂无 HAL/LL）、问题只能在 RTOS 运行时复现（如多线程竞态）。

## 1. 造裸机金标准（裸机侧工程）

1. **来源**：STM32Cube 参考工程（如 `Projects/38_SD_Card`）裁剪，或自写最小 main。
2. **目标**：只做一件事——**证明「硬件 + FSBL + 时钟/供电」能跑出结果**。
   - 例：TF 卡金标准 = 打印 `CardType/LogBlockNbr`；摄像头金标准 = 出图。
3. **烧录位置**：与 RTOS 镜像**同一槽位**（本例 `0x70100000`），FSBL 不动。
4. **加早期探针**（关键差异化）：
   - `[P]` 探针：在 `main()` 开头（`HAL_Init` 之前/之后可各放一个）跑「目标外设关键序列」，
     打印环境（`CTRL/PRIMASK/MPU_CTRL/CCR/SCTLR/MAIR/SAU/MSP/PSP`）+ 外设寄存器 + 序列结果；
   - `[QX]` 探针（杀手锏）：把序列**前移到 `HAL_Init()` 之前**——若此时失败，
     说明「裸机成功依赖 HAL 的前置初始化」，差集直接指向根因；
   - 探针打印函数用**裸 UART 寄存器直写**（不依赖库/中断/DMA）。

## 2. NuttX 侧对等探针

| 位置 | 用途 | 注意 |
|------|------|------|
| `__start_c` 中 `stm32_boardinitialize()` 之后（早期） | `[E3]` 环境 dump + 关键序列 | 此时**无调度器/无 D-Cache/无 tick**，最接近裸机 |
| 驱动 `init()` 开头 | `Q1` 类实验（对齐 MCU 状态后跑序列） | 驱动内实验**必须带外设复位** |
| `[E3D]` 变体 | 干净状态 + 变量（如 SPSEL=0） | 切换执行环境必须用 **naked 汇编** |

**对等原则**：双端探针必须「**同寄存器、同顺序、同格式**」，才能逐行 diff。
（例：都在外设初始化完成后 dump `CFGR/CFGR2/ICxCFGR/DIVENR/ENR/RSTR`。）

## 3. 探针矩阵（实验设计模板）

| 实验 | 位置 | 变量 | 回答的问题 |
|------|------|------|-----------|
| `[P]` 裸机默认 | 裸机 main | — | 硬件+FSBL 基线是否 OK |
| `[QX]` 裸机前移 | `HAL_Init` 之前 | 前置初始化被去掉 | 裸机成功**依赖哪个前置** |
| `[E3]` RTOS 早期 | `__start_c`（board init 后） | 执行环境 | 环境差异与否 |
| `[E3D]` 干净化 | 外设复位后 | SPSEL/CCR 等单项 | 排除可疑变量 |
| `Q1` 驱动内 | 驱动 init | 对齐若干项后跑序列 | 驱动路径可达性 |

**实验规矩**（血泪教训）：
- 每次实验**先复位外设**，否则跑在上一轮冻结状态机上 = **结果无效**（`[E3B]/[E3C]` 前车之鉴）；
- 切 SP/SPSEL 只能 naked 汇编（C 中途切栈 → 栈帧错乱 + `irq_unexpected_isr`）；
- 探针自身要「干净」：写 GPIO 前开**端口时钟**；跑完**复位外设**。

## 4. 反向实验设计法（本战术的核心创新）

正向着调（RTOS 对齐裸机）做不动时，**反过来**：

```
正向:  RTOS 侧不断补配置 → 对齐裸机  (容易陷入猜测循环)
反向:  裸机侧不断前移探针 → 剥掉前置 → 找出"成功的最小前置集"
       剥到哪一步失败, 那一步与失败侧(RTOS)的差集就是根因
```

**判定逻辑**：

| 裸机 `[QX]`（前移后） | RTOS | 结论 |
|----------------------|------|------|
| 失败 | 失败 | 差异在**前置初始化**（如 HAL_MspInit 的供电/时钟） |
| 失败 | 成功 | RTOS 侧已含该前置（罕见） |
| 成功 | 失败 | 差异在 RTOS **运行环境**（MPU/Cache/SPSEL/中断）→ 继续环境二分 |

## 5. 实战复盘（两案例如何命中）

### SDMMC / VDDIO4（反向实验的教科书案例）

1. `[P]` 裸机成功（卡识别）→ 金标准成立；
2. `[E3]`（NuttX 早期）+ `Q1` + 大量寄存器对齐后**仍失败** → 正向对照走到尽头；
3. **反向**：裸机 `[QX]` 把序列前移到 `HAL_Init` **之前** → 失败；
4. 差集 = `HAL_MspInit`（含 `HAL_PWREx_EnableVddIO4()`）→ 查 AN5967 引脚域表
   （SDMMC1 引脚全在 VDDIO4 域）→ **根因锁定 + 修复 = 一次点亮**。

### 摄像头 / IC17-IC18（同时点 diff 案例）

1. 双方都能初始化、都“看起来配置对”；
2. 同时点 dump `IC17CFGR/IC18CFGR` → 裸机 `0x00030000` vs NuttX `0x10030000`；
3. 分频比一致、**SEL 位不同**（0b00=PLL1 vs 0b01=PLL2）→ 宏编码错 → 修正后点亮。

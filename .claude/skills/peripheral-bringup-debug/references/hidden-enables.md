# 隐性使能位 / 陷阱检查清单

> 由实战案例提炼，**每次调试结束后把新命中的坑收录回本表**。
> 仅收录「隐性」项——即：配置看起来对、单一代码审计难发现、必须靠双端对照或实验暴露的坑。

## 1. 时钟门控（写寄存器被静默丢弃）

| 检查项 | 说明 | 验证手段 |
|--------|------|---------|
| 端口时钟（AHB4ENR 的 GPIOxEN） | 未开时钟时写 `MODER/AFR/OSPEEDR` 被丢弃，**读回是复位值** | 写后读回 + 与预期值 diff |
| 外设时钟（AHB5ENR/AHB4ENR/APBxENR） | `__HAL_RCC_xxx_CLK_ENABLE` 等价写法易漏 | 读 ENR 寄存器确认对应位 |
| **RCC 覆盖写陷阱** | `__HAL_RCC_*_CLK_ENABLE` 可能用 **WRITE_REG（非 SET_BIT）** → 多外设分开调用互相覆盖 | 检查 HAL 宏实现；多外设时逐一读回 |
| 总线域区分 | AHB4 vs AHB5 的 ENR 是**不同寄存器**（N6：GPIO=AHB4，SDMMC=AHB5） | 对照 memorymap 宏 |

## 2. 供电域（引脚无法驱动电平）

| 检查项 | 说明 | 验证手段 |
|--------|------|---------|
| VDDIO2/3/4/5 的 `SV`（supply valid）位 | 复位后未置位 → 该域引脚**无法输出任何电平**（命令/时钟全死） | 查 `PWR_SVMCR*` / 对应 `HAL_PWREx_EnableVddIOx()` |
| 电压范围 `VRSEL` | 1.8V vs 3.3V 选择（如 `VDDIO4VRSEL`） | 与参考程序对齐 |
| **引脚→域映射** | 必须查数据手册/AN 的 pinout 域表（例：N6 的 `VDDIO4 = PC[1],PC[12:6],PH[9,2]`，整套 SDMMC1 都在里面） | AN/DS 文档 grep 引脚名 |
| 症状特征 | **寄存器全正常、时序全对，引脚就是不动** | 当「命令状态机冻结」且一切配置对齐时，**优先怀疑供电域** |

## 3. 时钟源 / SEL 类位（值一致 ≠ 源一致）

| 检查项 | 说明 | 验证手段 |
|--------|------|---------|
| 外设时钟源 SEL（CCIPR/CCIPRx） | 宏编码错误时「分频值一致」但「源不同」→ 频率/行为错 | 逐位核对 SEL 字段 + 查 CMSIS `LL_RCC_*_CLKSOURCE_*` 编码 |
| ICn 分频器使能（DIVENR） | 缺 `ICxEN` → 该路径时钟静止 | 读 DIVENR 与参考程序 diff |
| 根因特征 | 摄像头黑屏案例：`stm32_rcc.h` 的 IC17/IC18 **SEL 宏值错**（0x1<<28=PLL2，应为 0x0=PLL1） | 一切「动态」都不信，**逐位读回** |

## 4. 复位 / 残留状态

| 检查项 | 说明 | 验证手段 |
|--------|------|---------|
| 实验前外设复位 | 冻结的状态机（如 `CPSMACT=1` 常驻）会让后续实验**全部无效** | `RSTSR(置位) → 延时 → RSTCR(解除)` |
| 探针污染 | 早期探针失败留下的 `CMD/STA` 残留会毒害驱动初始化 | 驱动 init 开头强制外设复位 |
| 复位寄存器别名 | N6: `AHB5RSTSR@0xA20` / `AHB5RSTCR@0x1220`（是不同地址的两个别名） | 查 CMSIS 权威偏移 |

## 5. 协议 / 步骤类（配置对但顺序错）

| 检查项 | 示例（SDMMC） |
|--------|--------------|
| 必要的附属命令 | **ACMD6（SET_BUS_WIDTH）**：控制器切 4-bit ≠ 卡切 4-bit；卡不发 4-bit 数据 → 无 start bit |
| 命令顺序 | **CMD9 必须在 CMD7 之前**（Standby 态），否则响应超时 |
| 响应语义 | CMD55/CMD2/CMD7/CMD16 等**必须按带响应发送**（等 R1/长响应）；当无响应发 → 状态机重叠冻结 |
| 数据路径启动 | `HWFC_EN → DTDIR → CMDTRANS 触发`（RM0486 步骤）；`DTEN` 禁止用于 SD 卡 |
| 时序等待 | 74 个 SDMMC_CK 上电窗口；超时寄存器 `DTIMER` 必须先配置（=0 立即超时） |

## 6. 流控 / FIFO 交互

| 检查项 | 说明 |
|--------|------|
| HWFC 停钟机制 | `HWFC_EN=1` 时数据中途「FIFO 不够空」会**冻结 SDMMC_CK**（传输像卡死） |
| 读取策略 | 必须**读到 `RXFIFOE` 彻底排空**（固定读 N 字会让 FIFO 永远不满足恢复条件） |
| 诊断指标 | `DCOUNT` 停滞 + `DATline_changes≈0` = 时钟被冻/卡停发；`DATline_changes≈循环数` = 时钟在跑 |

## 7. RTOS / API 约定类

| 检查项 | 说明 | 排查线索 |
|--------|------|---------|
| 块驱动 `read/write` 返回值 | **必须返回「扇区数」**，返回字节数会让 `fat_hwread` 恒判短读 → mount `-ENODEV` | 读框架源码（`fat_hwread` 的 `if (nsectorsread == nsectors)`） |
| `mount()` 错误码被吞 | 业务代码常 `if (ret < 0 && ret != -EBUSY && ret != -ENODEV)` 过滤 → **真实错误码不见** | 调试期无条件打印 ret+符号名 |
| `ferr/fwarn` 静默 | `CONFIG_DEBUG_*` 关闭时 error 级宏可能编译为空 → 「没日志」≠「没执行」 | 换 `syslog(LOG_ERR)` 或开 DEBUG 配置 |
| 上层设备注册 | `register_blockdriver` / `register_driver` 差异；VFS 要求 `geometry.geo_available` | 从上层框架反查字段语义 |

## 8. 高频「交付陷阱」（非驱动，但阻断验收）

| 陷阱 | 说明 |
|------|------|
| 卡未格式化 | 新卡无 FAT 扇区（全 0x00）→ mount 必失败；`mkfatfs` 默认只试 FAT12/16，**FAT32 需显式 `-F 32`**（>4GB 卡必用） |
| 空目录判断 | FAT32 根目录簇内容全 0 是**正常**（空目录），不是读失败 |
| 数据线无活动 ≠ 驱动错 | 先确认「对端（卡/传感器）是否真在发」——用 GPIO `IDR` 直接监测数据线电平和翻转次数 |

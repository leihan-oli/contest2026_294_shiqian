# 眼控界面（LVGL）设计

## 为什么是"网格 + 持续注视"

眼控和手指触摸的差别在于**误触代价**：眼球会不由自主地扫视。因此界面刻意做成：

- **大步长**：3×2 方形按钮网格（类似手机主页），一次位移只跨越一格
- **慢触发**：动作需要**持续注视 0.6~1.0 s** 才生效，扫视一眼不会触发
- **可回退**：左看 = 返回，闭眼 = 进入，两个动作语义正交

## 页面结构

```text
主页（3×2 网格）
├── 眼动识别展示   摄像头实时预览 + 判决文字（不执行动作）
├── 拍照           3 s 倒计时 → 全帧 800×480 BMP 存 /mnt/sdcard
├── 系统信息       内存 / 帧率 / LVGL 堆 / 版本 / 时间
├── LED 控制       LED0(PG10) / LED1(PE10) 开关
├── 串口命令       常用 eye_cam 子命令，可点选执行
└── 关于           版本、构建时间、openvela/NuttX、NPU 运行时
```

二级页内：**左看 = 返回**，**闭眼 = 确认/进入**，**右看 = 下一项**。

## 判决 → 动作映射

| 判决 | 网格页 | 二级页 | 音调 |
|---|---|---|---|
| CLOSED（闭眼） | 进入选中项 | 确认 / 触发动作 | **784 Hz (G5)** |
| LEFT（左看） | 上一个 | 返回 | **587 Hz (D5)** |
| RIGHT（右看） | 下一个 | 无 | **988 Hz (B5)** |
| OPEN / OTHER | 静息 | 静息 | 660 Hz (E5) |

触发时长按动作区分（进入页面 vs 触发执行），并在提示条上给出进度反馈。

## 字体方案

LVGL 内置字体不含中文，而界面需要中文。做法（`tools/UI字体/gen_eye_font.py`）：

1. **从系统 TTF 渲染**（NotoSansCJK），而不是用正点原子的 GBK 点阵字库 ——
   实测同字号下点阵字库"相/眼/控"等字笔画粘连，TTF 渲染清晰可读
2. **按实际文案裁剪字符集**，只保留界面真正用到的字：4 档共 1000+ 字形，
   比整档字库**省 58 KB**（48px 档省 40.5 KB）
3. 编码遵循 **LVGL 1bpp 连续位流**（像素跨行连续、行间不补齐），
   这一点用 LVGL 自带 `lv_font_unscii_8` 的真实数据反推验证过

| 档位 | 用途 | 字形数 |
|---|---|---|
| 64 px | 拍照倒计时大数字 | 16 |
| 48 px | 网格图标字 | 6 |
| 32 px | 页面标题 | 73 |
| 24 px | 正文/提示 | 215 |

## 渲染与内存

- 走 **LCD PARTIAL 路径**（`/dev/lcd0`）：单 framebuffer 下 DIRECT 模式会撕裂
- 开启 **Helium(MVE) 汇编加速**（`LV_DRAW_SW_ASM_HELIUM`），全屏 PARTIAL 刷新能跟上
  LTDC 扫描线，消除"块状滚动"
- LVGL 堆 192 KB 放**内部 RAM**（`LV_MEM_ADR=0x0`）：
  放 HyperRAM 实测会崩（`arm_busfault @ 0x90000014`）；帧缓冲 750 KB 由 LTDC 独占
- 改动这些数值后**务必**检查 `_ebss ≤ 0x34200000`（见 [reproduce.md](reproduce.md)）

## 内存占用

| 项 | 大小 |
|---|---|
| LTDC 帧缓冲（硬件必需） | 768,000 B |
| LVGL 堆 | 192 KB |
| 字库（4 档合计） | ~110 KB |
| 固件整体 | 948,064 B（上限 1 MiB） |

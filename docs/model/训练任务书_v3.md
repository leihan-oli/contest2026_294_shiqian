## 2. 训练

```bat
python train_blink.py --flat eye_photo --task blink --size 64x128 --epochs 60 --out models --batch 32 --lr 1e-3
```

和上次的命令**只差 `--epochs`**（上次默认 30，这次建议 60——样本数从 585 涨到 991，每轮看到的更多，但边界样本也更多，多跑几轮更稳）。

**如果显存/时间充裕**，可以试 `--epochs 100`；如果 val acc 在 40 轮后就不再涨，60 轮足够。

产物：`models/blink_best.pt`

## 4. 验收标准（**重点看 left/right**）

跑完 `train_blink.py` 会打印混淆矩阵。**必须检查这三条**：

### ① 总体 val acc ≥ 0.95

### ② `left` / `right` 召回 ≥ 0.85 —— **这是本次重训的核心指标**

**背景**：上一版模型在 board 上新数据上 `left` 召回是 **0/196**、`right` 是 **0/186**（判成了 open）。三个可能原因按可能性排序：

1. **构图变了**：宽高比从 2.07 变成 2.76，resize 到 2.0 时横向压缩 38%，而 left/right 的判据正是眼角那块眼白楔形，形状被改得最狠
2. **旧模型没学过这种构图**
3. 数据本身的问题（已排除：头偏检查显示 left/right 没有系统性偏转，眼白楔形清晰可见）

本次用**同一构图**训练，模型应该能适应新的压缩比例。**如果 left/right 召回还是低于 0.85，说明问题不在构图，而是在数据本身** —— 那时再看混淆矩阵里 left 被判成了什么，告诉 Linux 端，需要补采。

### ③ `open → left` 误判要接近 0

**上一版最严重的问题**：遮挡实验发现，旧模型把"眼睛下方那块（脸颊+鼻孔）"当成了"这是 open"的证据，遮掉它 4/5 张就翻成 left。真实场景里稍微换个距离/光照，这个捷径就崩，left 冒出来。

新数据**已经把鼻孔裁出框了**，理论上这条捷径没有了。**请确认混淆矩阵里 `open→left` 那一格接近 0。**

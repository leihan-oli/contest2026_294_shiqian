# ADR-0003：LVGL 与摄像头共用一个 framebuffer

## 状态
已接受

## 背景
板上只有一块 800×480×2 B = 750 KB 的 framebuffer（LTDC 直接扫描它）。
LVGL 需要"画"，摄像头需要"帧落进来"，两者都要这块内存。可选：

| 方案 | 说明 | 代价 |
|------|------|------|
| 双 framebuffer | 相机写一块、LVGL 画另一块 | +750 KB RAM；本 port 的 RAM 余量只有几百 KB，且 NPU 张量池卡在 `0x34200000` |
| **模式互斥 + 单 framebuffer** | 同一时刻只有一个"用屏者" | 需要严格的状态切换与帧冻结时序 |

## 决策
单 framebuffer，**眼控界面与相机预览互斥**：
- 界面模式下 LVGL 独占 `/dev/lcd0`；
- 需要识别时，摄像头把帧落到 `0x90100000`（HyperRAM）而不是屏上，
  应用再从那里读帧做裁剪与推理；
- 切回界面时由 LVGL 重绘。

## 后果
- ✅ 省下 750 KB RAM（也正是 LVGL 堆被压到 192 KB、字体按档裁剪的原因）。
- ✅ 相机写 HyperRAM 后，CHANGELOG 中的"每帧 2.7 s 冷启动"问题一并解决
  （`stm32n6_video.c` 的冷/热启动分离）。
- ⚠️ 引入了"何时冻结帧"的时序约束：必须在 `STREAMOFF` 冻结之后才读帧，
  否则会读到撕裂的半帧。

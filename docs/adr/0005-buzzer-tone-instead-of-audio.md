# ADR-0005：声音反馈方案 —— 蜂鸣器四音调

## 状态
已接受

## 背景
声音反馈最初设想的形态是"用喇叭播语音提示"（例如"已进入系统信息"）。为此做了完整尝试：
ES8388 codec + SAI1 + I2S + DMA，硬件链路全部核对过（引脚、时钟树、PLL2/IC7、
量化寄存器……），最终卡在一个具体现象上：

```text
sai: clock probe: fifo 5 of 8 left after about 2000 us (44.1 kHz wants 181)
```

**MCLK 正常输出、codec 能应答 I2C、寄存器读回全对，但 SAI 的 FIFO 从不排空**
（`FLVL` 恒为满）。已排除的假设列在 `docs/audio-buzzer.md`。

## 决策
产品的声音反馈采用**蜂鸣器音调**（PD3，无源蜂鸣器，TIM3 更新中断翻转 IO 产出方波）：

| 动作 | 音调 |
|------|------|
| 闭眼 / 确认 | 784 Hz（G5） |
| 看左 / 返回 | 587 Hz（D5） |
| 看右 | 988 Hz（B5） |
| 其他 | 660 Hz（E5） |

二级页面按住时连续响；菜单里的移动/进入在动作执行后响一声短音。

## 后果
- ✅ 交互反馈可用，且**不占用眼控主循环**（中断发声，不是忙等）。
- ✅ 用户可凭音高分辨动作，闭眼操作时不必盯着屏幕。
- 📎 喇叭（SAI + ES8388）播放路径的完整排查记录保留在 `docs/audio-buzzer.md`，
  作为后续扩展的起点：其中已确认两个可复用的事实 —— ES8388 需要 MCLK 才应答
  I2C，厂商初始化顺序是 SAI 先于 codec。产品当前的声音反馈以蜂鸣器音调为准。

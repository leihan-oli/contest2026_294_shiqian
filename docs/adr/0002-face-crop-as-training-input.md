# ADR-0002：训练输入改用"按脸框裁剪的眼图"

## 状态
已接受（这是对本项目原方案的**修正**，直接决定了 left/right 从"不可用"变为"可用"）

## 背景
第一版（v2）眼动模型是用**固定 ROI** 采的图训练的，而运行时喂给模型的是
**按人脸框裁剪**出来的眼图。两条链路的构图不同：固定 ROI 每张都是同一位置同一大小，
脸框裁剪则随坐姿、距离漂移。

板端实测结果很直白：

| 类别 | v2 召回 | 现象 |
|------|---------|------|
| open / closed | 可用 | 眼睑闭合是强特征，构图漂移扛得住 |
| **left** | **0 / 196** | 全部判成 open/closed |
| **right** | **0 / 186** | 同上 |

即"看了不该看的地方"——模型学的是固定构图下的像素分布，换构图就失效。

## 决策
**训练数据与推理输入走同一条链路**：板端新增"采集模式"，按**人脸框**裁剪眼图
（`crop_w = 2.0 × 瞳距`，眼心位于框内 `y = 0.413` 处）存 BMP 到 SD 卡，
这些图直接作为训练集。

## 后果
- ✅ 五类全部识别：自采 991 张，float 991/991、int8 990/991（板端实时运行）。
- ✅ 数据集几何可审计：`tools/dataset_audit/` 里是当时用过的几何/遮挡/头偏检查脚本。
- ⚠️ 代价是"要重采"：旧数据集作废，采集 991 张 + 人工剔除约 10%。
- 📌 可复用的教训：**先对齐上下游的输入分布，再谈模型和量化。**
  本项目在量化配置（calib 200 → 345）上花的力气，收益远小于这次构图对齐。

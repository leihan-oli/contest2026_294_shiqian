# 声音反馈：ES8388 喇叭（未打通）与蜂鸣器音调（已实现）

## 结论先行

| 方案 | 状态 | 结论 |
|---|---|---|
| ES8388 + SAI1 播放 WAV | ❌ 未打通 | 时钟链全部正确、MCLK 正常，但 **SAI FIFO 恒定不排空**，DMA 与 CPU 直灌均超时 |
| **蜂鸣器音调反馈** | ✅ 已上板 | PD3 无源蜂鸣器 + TIM3 中断翻转，按判决给不同音高 |

## 一、为什么先做喇叭（以及卡在哪）

目标：播放 SD 卡里的提示音（"识别到××，已进入××"）。硬件事实（来自正点原子
`44_Music_Player` 例程与 BSP，非推测）：

| 项 | 值 |
|---|---|
| 接线 | `PB2=SD_A` / `PC2=SCK_A` / `PB0=FS_A` / `PE2=MCLK_A`（SAI1，AF6） |
| 音频时钟 | HSE → PLL2 → IC7（`DIVENR.IC7EN`）→ SAI1 内核时钟 |
| 内核时钟选择 | `RCC_CCIPR7.SAI1SEL = 2`（IC7） |
| codec I2C | **软件模拟 I2C**，`PE13=SCL` / `PE14=SDA`，地址 0x10 |
| 麦克风/喇叭 | ES8388 内部 PA 直推，无独立功放使能脚 |

排查过程（每一步都在板上读回寄存器验证）：

| 假设 | 验证结果 |
|---|---|
| PLL2 没锁 | 已修正（开 HSE、置 `PLL2ON`、`SEL=HSE`）→ 锁上了 |
| `MCKDIV=0` 非法 | 修正为 2（HAL 公式 `CK/(Fs×256)`），`CR1=0x08232280` 读回正确 → **无变化** |
| 内核时钟源不对 | pclk2 / ic7_ck / hsi_div_ck 三种都试 → **FIFO 仍不排空** |
| 必须先 MCKEN 再 SAIEN | 按 RM0486 顺序执行并验证 `SAIEN=0` 保持 → 仍无数据搬运 |
| GPIO 安全属性（`SECCFGR`）阻断 | 实验后无变化 |
| DMA 通道/安全位 | 通道重置、安全位、`CSAR/CDAR` 读回全部正常，只搬 5 半字后停 |
| errata / 厂商 MSP 顺序 / F3·F7·L4 的 SAI 驱动对照 | 未发现遗漏 |

**最终症状**：写入 4 个字并置 `SAIEN` 后，`FLVL` 恒为 5（=FIFO 满），2 ms 内一字未发。

两个**有长期价值的事实**（下次继续时从这里开始）：

1. **ES8388 需要 MCLK 才应答 I2C**：冷启动（SAI 复位、无 MCLK）时 `audio: codec write 00 failed`；
   先置 `CR1.MCKEN=1`（`SAIEN=0`）后 codec 立刻应答 —— 厂商顺序也是"SNAI 先于 codec"
2. **SAI 的 MCLK 输出是好的**（codec 有应答即证明），只有 FIFO→移位器这一段不动

> 另注：`SAI_xSR.FREQ` 位是 **"FIFO 请求"**，不是错误标志（RM0486 §68）；`FLVL` 是档位
> （0=空 … 5=满），别把它当成"剩余量"。

## 二、蜂鸣器（已实现）

### 硬件

```
PD3 ──R66(1K)──▶ Q7(三极管基极) ──▶ 蜂鸣器 ── VCC3.3
```

- 三极管驱动，PD3 高 = 导通
- **无源**（需要方波）：用 `eye_cam tone 400` 与 `tone 3000` 对比听感确认，音高明显不同
  （有源蜂鸣器则无法变调 —— 用耳朵判定最可靠）

### 实现（`board/atk-dnn647/src/stm32n6_buzzer.c`）

| 接口 | 说明 |
|---|---|
| `stm32n6_buzzer_beep(ms)` | 纯 GPIO 开关（"咔"一声） |
| `stm32n6_buzzer_beeps(n, on, gap)` | 短促连响 |
| `stm32n6_buzzer_tone(hz, ms)` | 阻塞式发音（自检用） |
| `stm32n6_buzzer_tone_async(hz)` | **非阻塞**持续音：TIM3 更新中断每半个周期翻转 PD3 |
| `stm32n6_buzzer_tone_stop()` | 停音并拉低引脚（空闲调用安全） |

要点：

- **不能用忙等发持续音**：眼控循环本身要判断"动作是否还在保持"，忙等会把判决饿死
- **TIM3 在本工程空闲**（TIM2=`/dev/timer0`、TIM5=`/dev/oneshot`），1 MHz 时基，
  `ARR = 500000/hz - 1`，更新中断频率 = 音调 ×2
- 板级文件需要 `#include <arch/board/board.h>` 才能取到 `STM32_APB1_TIM_FREQUENCY`

### 眼控音调策略

| 事件 | 声音 |
|---|---|
| 二级页按住某动作 | 该动作音调**连续**响（直到动作触发或视线变化） |
| 菜单移动 / 进入 / 返回等动作完成 | **一声短音**（90 ms，同音调） |
| 闭眼 | 784 Hz (G5) |
| 左看 | 587 Hz (D5) |
| 右看 | 988 Hz (B5) |
| 其它 | 660 Hz (E5) |
